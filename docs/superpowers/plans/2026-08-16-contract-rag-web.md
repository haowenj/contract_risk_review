# Contract RAG Web Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有合同 RAG 脚本整理成一个后端渲染的最小 FastAPI 应用，支持 PDF 上传、后台入库、索引持久化/恢复、合同状态、单问题问答和 RAG 调试信息。

**Architecture:** 保留现有 MinerU、清洗、跨页合并、Context、Node、Embedding、Retriever、Rerank、Evidence Selector 和 Answer Generator 模块，在其外新增 `app/` 应用层。`ContractProcessor` 负责一次性入库，`IndexManager` 负责内存缓存与磁盘恢复，`ContractService` 负责合同和问答用例；`main.py` 暴露 FastAPI app 和服务端渲染路由。

**Tech Stack:** Python 3.14+, FastAPI, Starlette TestClient, Jinja2 templates, SQLite (`sqlite3`), LlamaIndex `StorageContext`/`load_index_from_storage`, 现有 httpx、LangChain 和 MinerU 客户端。

**Spec:** `docs/superpowers/specs/2026-08-16-contract-rag-web-design.md`

## Global Constraints

- 第一版只接受 PDF。
- 不通过 subprocess 调用 Python 脚本；后台任务直接调用现有 Python 函数。
- 不引入 Qdrant、Redis、Celery、LangGraph、Vue、React 或其他额外基础设施。
- 使用 FastAPI `BackgroundTasks` 完成第一版入库任务。
- 使用 SQLite 保存合同基本信息和处理状态。
- 每份合同使用独立 `contract_id` 和独立目录。
- 使用 LlamaIndex `storage_context.persist()` 保存索引，使用 `load_index_from_storage()` 恢复；问答阶段禁止重新向量化。
- 每个问题独立检索，不实现多轮上下文理解。
- 页面由 FastAPI 后端渲染 HTML；不做前后端分离，不建立独立前端工程。
- 不覆盖或回滚用户在任务开始前已经存在的工作区改动。
